# ADR-0012: The `faststudio` command-line interface

- Status: Accepted (2026-11-25, maintainer approval with amendments A1–A7)
- Date: 2026-11-24
- Plan: docs/plans/v0.2.md

## Context

v0.1 asks users to copy a `create_admin.py` script. Recovering from a lockout
(ADR-0009) and setting up permissions also need a supported tool.

## Decision

1. **Console script** `faststudio`, built on stdlib `argparse`, with no new
   dependency. Commands:
   - `faststudio createadmin --app module.path:admin [--username U] [--set field=value ...]`
   - `faststudio changepassword USERNAME --app module.path:admin`
   - `faststudio syncpermissions --app module.path:admin [--dry-run] [--prune [--yes]]`
2. **`--app`** imports `module.path` and takes the attribute after `:`. That
   is either an `Admin` instance or a zero-argument callable returning one
   (app factories). Errors are short messages with no tracebacks, as in the
   v0.1 example CLI.
3. **Passwords** are read only through `getpass`, twice, and compared. They
   are never accepted from argv or environment variables. They are checked by
   the backend's validators (`user_admin.validators`) before hashing.
   - If stdin is not a TTY, the command refuses with exit code 2, because
     `getpass` would otherwise echo the input.
   - Tests inject a password-reader callable.
4. **User management** goes through the backend's `user_admin` capability
   (ADR-0011), whose methods take an `AsyncSession`. Backends without it give
   a clear error naming the capability.
   - `ModelUserBackend` implements it. `createadmin` sets `is_admin` and
     `is_active`. It prompts for the username and for every required column
     without a default (the README model's `email`); `--set field=value`
     supplies other values, and missing ones fail with a message naming the
     columns.
   - `contrib.auth` sets `is_superuser`.
   - The CLI never creates tables. If the table is missing, it says to run
     the migrations or `create_all` first.
5. **`syncpermissions`** is idempotent.
   - It creates the missing `<identity>.<action>` permissions and the
     `extra_permissions`, and updates their names. An `IntegrityError` from a
     concurrent worker is tolerated.
   - `--dry-run` lists missing, stale and orphaned codenames.
     - **Stale:** in the database but no longer produced by any registered
       model action or `extra_permissions` entry, including codenames left
       behind by a renamed `identity`.
     - **Orphaned:** a stale codename that still has assignments.
     - Renaming an identity makes its old codenames stale; this is
       documented.
   - It never deletes anything unless `--prune`. `--prune` deletes only stale
     codenames, together with their assignments, after listing them. It asks
     for confirmation by default; `--yes` skips the prompt for CI. Without a
     TTY and without `--yes` it refuses. Passwords are never
     non-interactive.
   - `Admin(sync_permissions_on_startup=True)` runs it lazily on the first
     request, under an `asyncio.Lock` created inside the running loop,
     because mounted sub-apps get no lifespan events. It never prunes. A
     failed sync is logged and retried on a later request; requests keep
     being served, and missing grants fail closed.
6. **Each command runs in a single `asyncio.run`** and disposes the engine.
   Database errors print only the exception type, as in v0.1.

## Consequences

- The README and `examples/basic` switch to the CLI. The `create_admin.py`
  and `restore_admin.py` snippets stay in getting-started under "Without the
  CLI" for v0.2, still tested, and are removed in v0.3.
- The CLI is a supported recovery path for locked-out installations.
